## v0.6：自托管运行加固

参考 Miniflux、changedetection.io、RSSHub 和 Healthchecks 的成熟模式，保留当前轻量架构，不引入 Redis、Celery 或额外数据库。

### 关键变化

- 使用同一镜像运行 `web` 与 `scheduler` 两个 Compose 服务，避免一次采集失败拖垮网页。
- 容器以非 root 用户运行，默认只绑定服务器本机端口，并配置自动重启、健康检查和日志大小限制。
- 数据、日志与 Vault 分别使用持久卷；主配置只读，UI 设置写入数据卷中的独立 JSON。
- 调度器每分钟写入状态心跳，记录任务开始、成功、失败、跳过和下次运行时间。
- 服务器重启后发现快照过期会自动补跑；可选接入 Healthchecks.io 兼容心跳。
- BLS 官方 ICS 每周自动校正非农、CPI、PPI，其他官方日程继续采用审慎的核对快照。
- 所有采集器恢复 TLS 证书验证，通用全文抓取增加指数退避重试。
- 日志改为午夜轮转并默认保留 14 天。

### 运维边界

默认部署不得直接暴露公网。推荐通过 SSH 隧道、Tailscale，或带 HTTPS 与身份认证的反向代理访问；内置 Basic 认证只作为轻量保护。

## v0.5：全球财经日历

### 目标

把“今天要读什么”向前延伸为“未来什么时候必须提高警觉”。日历不追求事件数量，而是按资产定价影响收录一级与二级事件，并统一换算为北京时间。

### 实现

- 新增 `ui/economic-calendar.json`，保存经过官方日程核对的事件、重要性、观察重点、影响资产与来源。
- 新增 `/api/calendar` 与 `/api/calendar.ics`，支持页面读取和导入个人日历。
- Web UI 新增地区、类型与 30/90/全年范围筛选，并突出下一风险窗口。
- 当前覆盖美联储与美国核心就业/通胀/增长数据，中国核心数据与 LPR，以及欧洲、英国、日本、加拿大、澳大利亚、新西兰和巴西央行。
- 精确时刻尚未公布的会议明确标记为“时间待定”，避免制造虚假精度。

### 更新边界

当前是本地官方计划快照，不会自行联网刷新。页面每次刷新会读取最新本地 JSON；官方调整日程后需要重新核对并更新数据文件。完整分级和来源见 `docs/economic-calendar.md`。

## v0.4：反方审查与观点账本

### 目标

每条高优先级信号不再止于“看起来利多或利空”，而是形成一条可被后续市场验证的假设：

1. 主逻辑：事件如何改变预期、现金流或风险溢价。
2. 反方观点：支持相反结论的最强证据或传导机制。
3. 失效条件：出现什么事实或价格行为时，应放弃原判断。
4. 复盘目标：选择一个可观察指标、预期方向和复盘周期。

### 数据结构变化

信号新增以下字段：

| 字段 | 含义 |
|---|---|
| `counter_argument` | 最强反方观点，禁止只把原结论简单取反 |
| `review_metric` | 复盘指标的人类可读名称 |
| `review_symbol` | 用于自动检查的行情代码 |
| `expected_direction` | `up`、`down` 或 `observe` |
| `review_horizon_days` | 1–30 天的复盘周期 |

### 复盘流程

```text
交易信号入选
  → 写入 SQLite 观点账本
  → 保存当时的指标价格作为基准
  → 每次采集时刷新最新价格
  → 到期后的首次运行计算价格变化
  → 自动标记：得到支持 / 已被证伪 / 尚不明确 / 等待数据
  → 用户可以在 Web UI 中覆盖机器结论
```

观点账本位于 `data/thesis_reviews.db`。系统使用 SQLite，是因为当前产品明确保持本地运行，不需要引入远程数据库或账号体系。

### 自动判断规则

- `up`：到期涨幅超过阈值则“得到支持”，反向变化则“已被证伪”。
- `down`：到期跌幅超过阈值则“得到支持”，反向变化则“已被证伪”。
- 绝对变化小于阈值：标记为“尚不明确”。
- 没有可用行情或只适合定性观察：标记为“等待数据”，保留人工复核。
- 默认阈值为 0.3%，可通过 `review_move_threshold_pct` 调整。

自动结果只回答“指定价格方向是否兑现”，不等于证明整条因果链正确。人工复盘优先于自动标签，并保留自动结果用于审计。

### 当前可自动检查的变量

复用现有 `yfinance` 行情层，可检查标普、纳指、恒生、上证、美国 10 年期收益率、美元指数、美元兑人民币、原油、黄金、铜、比特币和 VIX。它们既包括价格，也包括利率、波动率和美元等常用宏观代理变量。

官方经济数据发布值（如 CPI、非农、社融）目前仍作为人工观察项。后续若接入 FRED 或国内官方数据接口，应使用“发布日期可追溯”的历史快照，避免回测中的未来数据泄漏。

### UI 变化

- 信号详情新增“反方审查”和明确的“失效条件”。
- 新增“观点账本”区域，展示创建日、到期日、复盘指标、预期方向和到期变动。
- 支持人工标记“兑现 / 证伪 / 不明确”，结果写入 SQLite，而不是只保存在浏览器。
- 示例数据保留演示卡片，但不会写入真实账本。

### 设计取舍

- 没有整体引入 TradingAgents。当前目标是过滤信息和训练判断，不是让十几个 Agent 自动交易。
- 借鉴其角色分工、反方辩论和决策记忆，但仍使用单次结构化分析，控制延迟、成本和重复文本。
- 自动复盘采用确定性价格计算，不让 LLM 自己判断自己是否正确。

## 后续迭代候选

1. 接入带发布日期的宏观数据源，自动检查 CPI、就业、社融等非价格指标。
2. 增加按主题、资产和时间周期统计的命中率，但避免把少量样本包装成策略收益。
3. 记录“判断正确但交易表达错误”和“价格正确但逻辑错误”这两类差异。
4. 为观点账本增加 CSV 导出和月度复盘报告。
